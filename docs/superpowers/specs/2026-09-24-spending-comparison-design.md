# Дизайн: вкладка «Сравнение» на странице статистики

## Проблема

На `/stats` сейчас два фиксированных виджета: категории за один месяц и общая
динамика доходов/расходов. Нельзя ответить на вопрос «сколько я тратил на
продукты, сладости, фастфуд и гигиену в каждом месяце этого года» — ни по
выбранным категориям, ни по выбранным контактам (Евроопт, Санта, BurgerKing…).

Требования собраны на брейншторме с пользователем и проверены на интерактивном
макете с реальными суммами из локальной копии базы:
https://claude.ai/artifact/4XS9fiHdE7sb6VHSVrR5aw (макет утверждён пользователем
2026-09-24). Ниже — принятые решения, не гипотезы.

## Цель (фаза 1)

1. На `/stats` появляются табы «Обзор | Сравнение». «Обзор» — существующие
   графики без изменений. «Сравнение» — новая аналитика.
2. Разрез «Категории | Контакты» — строки матрицы берутся из одного источника.
3. Мультиселект с поиском и пунктом «Все».
4. Период — диапазон месяцев «с — по» (не больше 24 месяцев) плюс пресеты
   «3 мес», «6 мес», «12 мес», «С начала года».
5. Сводка (4 плитки), stacked bar chart по месяцам, таблица-матрица.
6. Выбор живёт в URL и восстанавливается из localStorage при заходе без
   параметров.

## Не входит в фазу 1

- **Фаза 2 — дриллдаун:** клик по ячейке таблицы открывает существующий
  `CategorySummaryDialog` / `ContactSummaryDialog` за этот месяц
  (`getCategoryOperationsInputSchema` / `getContactOperationsInputSchema` уже
  принимают `start`/`end`). Отдельный спек и план после релиза фазы 1.
- Кросс-фильтр «категории в конкретном магазине».
- Доходы в сравнении — только расходы.
- Именованные сохранённые наборы (пресеты в БД).
- Пересчёт по сегодняшнему курсу — суммы по курсу на дату операции.

## Данные и API

### Эндпоинт

`GET /api/operations/monthly-breakdown?by=category|contact&from=YYYY-MM&to=YYYY-MM`

Возвращает разреженные ячейки по **всем** категориям/контактам household за
диапазон. Фильтр по выбранным id делается на клиенте: включение/выключение
строк мгновенное, без рефетча, а объём ответа мал (45 категорий × 24 месяца —
потолок ~1000 ячеек, реально намного меньше; для 151 контакта — аналогично
разреженно).

### Контракты (`packages/contracts/src/operation.ts`)

| Тип | Поля |
|---|---|
| `getMonthlyBreakdownInputSchema` | `by: 'category' \| 'contact'`, `from: 'YYYY-MM'`, `to: 'YYYY-MM'`; refine: `from <= to`, длина диапазона ≤ 24 месяцев |
| `MonthlyBreakdownCell` | `referenceId: string`, `month: 'YYYY-MM'`, `totalMinor: number` |
| `MonthlyBreakdown` | `baseCurrency`, `by`, `from`, `to`, `cells: MonthlyBreakdownCell[]` |

Регэксп месяца переиспользуется из `getMonthlyExpenseSummaryInputSchema`
(вынести в общий `monthKeySchema`, если он ещё не выделен).

### Репозиторий

Новый метод `OperationRepository.listMonthlyReferenceBreakdown(householdId,
start, end, referenceColumn)` по образцу `listMonthlyReferenceExpenses`:
один запрос с `GROUP BY reference, strftime('%Y-%m', happened_on)`.

Фильтры:
- `type = 'expense'`
- `deleted_at IS NULL`
- `transfer_id IS NULL` — явное исключение переводов (урок `dcb0287`)
- `reference IS NOT NULL`
- `happened_on` в `[первый день from, последний день to]`

Сумма — `amount_in_household_base_currency_minor` (курс на дату операции), как
и на существующей `/stats`, чтобы цифры на двух вкладках не расходились.

### Сервис и HTTP

`OperationService.getMonthlyBreakdown(userId, input)` резолвит household,
переводит месяцы в даты и вызывает репозиторий. Контроллер
`operationController.monthlyBreakdown()` — по образцу `categoryStats()`:
`safeParse` → `invalidInput` (400) при ошибке валидации.

Схема БД не меняется, миграций нет.

## Клиентская модель

Чистые функции в `apps/web/src/views/statistics/lib/`, без Solid, покрыты юнит-тестами.

### `buildBreakdownMatrix(cells, selectedIds, months, references, currentMonth)`

Возвращает `{ months, rows, series, folded, hiddenZero, colTotals, total, avg }`:

- **rows** — выбранные строки с `values[]` по месяцам, `total`, `avg`, `budget`
  (только для категорий: `monthlyBudgetMinor`). Отсортированы по `total` по
  убыванию. Строки с нулём за весь период исключаются, их число — `hiddenZero`.
- **avg** (у строки и в итогах) — среднее **только по закрытым месяцам**
  периода (`month < currentMonth`). Текущий неполный месяц в среднее не
  входит; если закрытых месяцев в периоде нет — `null` («—»).
- **series** — то, что рисует график: если строк ≤ 8, все; иначе 7 крупнейших
  плюс синтетическая серия «Остальные (N)» с суммой свёрнутых строк по месяцам.
  Итог месяца на графике остаётся точным.
- **colTotals / total** — суммы по всем `rows`, не только по графику.

### Цвета серий

`category.color` не используется: в живых данных у «Продуктов» и «Сладостей»
одинаковый `#61be54`, в стеке они сливаются. Серии берут цвет из
фиксированной категориальной палитры на 8 слотов (skill `dataviz`, проверенной на дальтонизм,
отдельные ступени для светлой и тёмной темы — как токены в
`shared/styles/tokens.scss`). «Остальные» — нейтральный токен.

Цвет следует за сущностью, а не за рангом: `assignSeriesSlots(chartedIds, prevMap)`
сохраняет слот за строкой, пока она на графике; новая строка занимает
наименьший свободный слот. Карта слотов хранится в localStorage вместе с
выбором. Точка цвета в чипе, легенде, таблице и тултипе — одна и та же.

### Пресеты периода

`resolvePeriodPreset(preset, currentMonth)`: `3`/`6`/`12` — последние N месяцев
включая текущий; `ytd` — с января текущего года по текущий месяц. Кнопка
пресета подсвечена, когда текущий диапазон ему соответствует.

## UI (`/stats?tab=compare`)

### Структура

- Табы «Обзор | Сравнение» над содержимым страницы; `tab` в URL, по умолчанию
  `overview`.
- Панель управления:
  - сегмент «Категории | Контакты»;
  - кнопка мультиселекта «Категории: 4 ▾» + ряд чипов выбранного;
  - «Период»: пресеты + два селекта месяца «с — по» (опции ограничены: `from ≤ to`,
    не позже текущего месяца, не раньше первой операции household — первый
    месяц берётся из уже существующего `getMonthlyTrend().points[0].month`;
    если операций нет, нижняя граница — 24 месяца назад).
- Сводка — 4 плитки: «За период», «В среднем» (за закрытый месяц),
  «Последний закрытый» (% к предыдущему месяцу, рост — `--color-danger`,
  падение — `--color-success`), «Текущий месяц» (с пометкой, что месяц идёт).
- Легенда + stacked bar chart (`solid-chartjs` / `chart.js`, уже в зависимостях):
  - тултип на столбец: все ненулевые серии месяца с точными суммами и «Итого»;
  - текущий месяц — вторая строка подписи оси «неполный» (в макете была пунктирная обводка; в chart.js подпись проще и так же заметна);
  - ось Y с круглым шагом.
- Таблица-матрица:
  - первая колонка sticky, на узком экране горизонтальный скролл;
  - колонки: месяцы хронологически, текущий справа, курсивом с подписью «неполный»; затем «Итого», «Ср./мес», «Бюджет» — колонка только если хотя бы у одной строки есть бюджет;
  - строка «Итого»;
  - ноль отображается как «—»;
  - суммы округлены до рубля, точные значения — в тултипе графика;
  - месяц с превышением бюджета категории — `--color-danger-soft` фон и `--color-danger` текст, `title` с суммой превышения;
  - под таблицей сноски: про среднее, про скрытые нулевые строки, про свёрнутые «Остальные», легенда подсветки бюджета.
- Пустые состояния: ничего не выбрано («Выберите категории»; мультиселект стоит прямо над подсказкой, отдельной кнопки нет);
  за период по выбранным трат нет.

### Мультиселект

- Список отсортирован по сумме трат за выбранный период (по убыванию), рядом
  с каждым пунктом — сумма. Архивные категории/контакты доступны с пометкой «архив».
- Поиск по подстроке, без учёта регистра.
- **Пункт «Все»** — первым в списке:
  - клик, когда выбрано всё → снимает выбор со всех;
  - клик в любом другом состоянии → выбирает все элементы;
  - состояние выводится из выбора, отдельно не хранится: `checked`, когда выбраны все;
    `indeterminate` при частичном выборе. Поэтому, если отметить последний невыбранный
    пункт, «Все» включается само, а если снять любой — выключается;
  - пока в поле поиска есть текст, пункт «Все» скрыт — чтобы не было
    неоднозначности «все найденные или все вообще».
- Лимита на количество выбранных нет.
- Чипы: при выборе всех — один чип «Все категории (N)» / «Все контакты (N)» с ×;
  иначе до 8 чипов и чип-кнопка «+ ещё N», открывающая список.
- Счётчик в подвале: «выбрано X из N», кнопка «Очистить».
- Закрытие по клику снаружи слушает `pointerdown`, а не `click`:
  перерисовка списка отсоединяет цель клика до того, как он всплывёт (баг
  найден на макете).

### URL и восстановление

Схема `statisticsSearchParamsSchema` (по образцу `homeSearchParamsSchema`,
через `createRouteSearchParams`):

| Параметр | Значение |
|---|---|
| `tab` | `overview` \| `compare` (`.catch` → `overview`) |
| `by` | `category` \| `contact` (`.catch` → `category`) |
| `from`, `to` | `YYYY-MM`; невалидное → пресет «С начала года» |
| `ids` | id через запятую, либо `all` |

`ids=all` сериализуется, когда выбрано всё: URL остаётся коротким. Семантика
при этом «все на момент открытия» — клиент разворачивает `all` в текущий
список сущностей.

При заходе без `ids` выбор для текущего `by` восстанавливается из localStorage
(ключ на разрез, try/catch). Неизвестные id — удалённые или из другого
household — молча отбрасываются. Если сохранённого выбора нет, показывается
пустое состояние.

### Стили

SCSS-модули рядом с компонентами, mobile-first (`mx.media-mn`), без
`!important`, только токены из `shared/styles/tokens.scss` (AGENTS.md).
Числа — `font-variant-numeric: tabular-nums`.

## Ошибки

- API: невалидный вход → 400 с сообщением из схемы; неавторизованный → 401.
- UI: ошибка загрузки → существующий `ErrorBoundary` страницы статистики.
- Пока идёт рефетч при смене периода или разреза, показываются предыдущие данные.

## Тестирование

- **API** (`apps/api/tests/operation-stats-service.test.ts`, `DATABASE_URL=:memory:`):
  - группировка по месяцам и reference;
  - исключение доходов, удалённых операций, переводов и операций без reference;
  - включительные границы диапазона — первый и последний день;
  - оба разреза;
  - изоляция household.
- **Контракт:** `from > to` и диапазон > 24 месяцев отклоняются.
- **Web unit** (`apps/web/tests/`):
  - `buildBreakdownMatrix`: сортировка, скрытие нулевых строк, среднее без текущего месяца, fold при > 8, точность итогов;
  - `assignSlots`: стабильность цвета при добавлении и удалении;
  - `resolvePeriodPreset`;
  - логика «Все»: toggle, индикатор, авто-включение на последнем элементе;
  - парсинг и сериализация search params, включая `ids=all` и мусор.
- **Визуально**, через браузер на локальном стенде, десктоп и мобильный вьюпорт:
  - проверить композицию и отступы, а не только работоспособность;
  - сценарий «Контакты → Все»;
  - тёмная тема.

## Деплой

Миграций нет. Порядок по сложившемуся процессу:

1. Коммиты в `master`, push. Локальный master и origin сверены.
2. Бэкап прод-базы перед деплоем, хотя схема не меняется: правило «прод-база
   должна выжить любой ценой».
3. На сервере — `git pull` в `~/sites/i-finances`, пересборка через compose
   homelab. Руками ничего не копируется.
4. Smoke на `https://i-finances.nikkeyl.com/stats?tab=compare`:
   - данные грузятся;
   - «Все» работает;
   - цифры «Обзора» совпадают со «Сравнением» за тот же месяц.
