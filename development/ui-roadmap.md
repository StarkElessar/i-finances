# Дорожная карта UI i-finances

Версия 2026-10-18 (решения владельца по вопросам 1–4 внесены, добавлены набор знаков валют, переезд на Vite 8 и правила исполнения). Цель: макет и кит как единый источник правды, ноль литералов в `apps/web` (только токены и компоненты `shared/ui`), Storybook на каждый компонент, затем приём других пользователей (IF-10).

Порядок для любой задачи: **доска в макете, согласованная владельцем, затем компонент в коде, затем история Storybook**. Задача, у которой нет доски, сначала получает доску.

## Правила исполнения (решение владельца 2026-10-18)

- Простые задачи делает Haiku, задачи посложнее Sonnet, всё ревью делает Opus. Сложные решения принимает Opus и документирует (в `development/decisions/` или в разделе задачи этой карты, с причиной и отвергнутыми вариантами).
- Простое (Haiku): механическая чистка по готовому правилу, правка значений токенов, перенос файлов, заготовки историй Storybook, обновление реестра в скиле.
- Среднее и сложное (Sonnet): компоненты кита, экранные задачи, API, миграции кода. Опасное (миграции данных, auth, изоляция окружений) всегда проходит ревью Opus до слияния.
- Ревью (Opus): каждый коммит с кодом проходит ревью до `push`; найденные дефекты возвращаются исполнителю.
- Деплой и миграция данных на проде выполняются только по явному слову владельца.
- Мак на время работы держится от сна (`caffeinate`), крышка открыта.

Источники: макет https://claude.ai/artifact/De31TDNR7feRASBZ73Leq1, решения в `development/ui-mockup.md`, аудит в `development/ui-audit.md`, реестр «доска → код» в `.claude/skills/ifinances-ui/SKILL.md`, задачи в Ticket Board (IF-N).

- Большие экранные файлы: `views/home/page.tsx` (1341 строка), `views/receipts/page.tsx` (1095). Экранные задачи по ним размера L.

- «Безопасность»: пункт в `widgets/app-header/ui/profile-menu.tsx` выключен. В API есть только регистрация и вход по ключу (`/api/auth/passkey/*`), вход и выход по паролю, смена имени. **Поля для раздела в БД уже есть:** `sessions.last_seen_at` (обновляется с троттлингом в `session-service.ts`), `ip_address`, `user_agent`; `webauthn_credentials.device_name`, `last_used_at`. Миграция схемы, скорее всего, не нужна.
- Household: таблицы `households`, `household_members` (роли `owner`/`member`) есть. `household-resolver.ts` создаёт `default-household` и бросает ошибку, если окружений несколько. В этом файле три класса, что нарушает правило «один класс — один файл»; разнести в IF-10. У `users` нет email, `password_hash` обязателен.

### Этап 2. Ограждения: линт и Storybook

**Цель:** новый литерал не проходит `pnpm lint`, у каждого компонента есть место для истории.

- **IF-40** (после IF-14): stylelint запрещает hex, `rgb()`/`hsl()`, числовой `z-index`, сырой `@media` и `!important` вне `shared/styles`; ESLint запрещает `style={{}}` с литералами и `Intl.NumberFormat` вне `shared/lib`. Lint запускается с `--max-warnings 0`, поэтому правила включаются сразу как error со списком исключений по файлам. Список сокращается по мере этапа 5. `px` и `fn.rem(N)` запрещать позже: их 400, и сначала нужна шкала размеров.
- **IF-30** (после IF-14): Storybook для Solid + Vite в `apps/web`, токены, переключатель темы, шрифт. Истории для существующих компонентов `shared/ui` (их 17).

**Готово, когда:** `pnpm lint` зелёный, список исключений лежит в конфиге с комментарием «снять в IF-N»; `pnpm storybook` и `build-storybook` работают, у каждого компонента `shared/ui` есть история в обеих темах.
**Размер:** IF-40 S–M, IF-30 M.
**Риски:** `storybook-solidjs-vite` поддерживается сообществом, совместимость с Vite 7 и `typescript7` не проверена: сначала пробный запуск в ветке. Общий конфиг `@stark/stylelint-config` живёт в отдельном репозитории: правила класть в локальный `stylelint.config.js`.

## Параллельно и последовательно

**Строго последовательно:** IF-23 → IF-35 → IF-20 → IF-21 → IF-16 → IF-13. IF-14 → IF-40 → снятие исключений по экранам → IF-34. IF-36 + IF-41 → IF-33 → IF-10.

**Параллельно:**
- поток «бумага» (IF-23, IF-35, IF-36, IF-37) и поток «основа» (IF-14, IF-30, IF-40) не пересекаются по файлам;
- IF-41 (API) можно начинать сразу;
- IF-17 и IF-15 сразу после IF-14;
- экраны IF-18, IF-19, IF-39 параллельно друг другу после IF-20/IF-21, но не параллельно IF-16 и IF-13 (общие файлы `views/home`).

**Можно отдавать агентам автономно:** IF-14, IF-40, IF-30, IF-17, IF-15, IF-41, IF-13, код IF-20, IF-21 и IF-32 по принятым доскам, чистка литералов по экранам. Агент сам проверяет в браузере на 390/768/1024/1280 и прикладывает скриншоты.

**Нужен владелец:** приёмка каждой новой доски (IF-23, IF-35, IF-36, IF-37, IF-38, IF-42), ревью IF-31, визуальная приёмка экранов этапа 5, деплой и миграция цвета категорий.

## Решения владельца 2026-10-18

Ответы на четыре вопроса прошлой версии карты и сопутствующие решения.

1. **Цвет категории: ключ палитры `k-1`…`k-10`, свой цвет запрещён.** Существующие hex переводятся на ближайший ключ новой миграцией данных (старые значения не трогать, сначала на копии БД, с бэкапом). Счета и контакты пока на текущем выборе. Разблокирует IF-19 и часть IF-14.
2. **Знак валюты там, где SVG не встаёт** (Chart.js, `title`/`aria-label`, нативный `<option>`, MCP): рекомендация принята, то есть суммы на графиках без знака, валюта кодом в заголовке оси или легенды, в атрибутах код. **Дополнение владельца:** нарисовать или подобрать в одном стиле знаки популярных валют: гривна, белорусский рубль (официальный 2026), российский рубль, китайская юань/йена (¥, CNY), евро, доллар, злотый. Это IF-42 (доска `Kit-Currency`), знаки используются в `money` через `currency-sign` (IF-32).
3. **Select и поле даты нативные** (в оболочке кита), свой Combobox с поиском; шрифт в полях на тач не меньше 16 px. «Идеальные свои» пикеры нарисовать позже, отдельной задачей, когда придёт время. Разблокирует IF-35 и IF-20.
4. **Household v1:** пользователь состоит только в одном окружении. **Регистрация и вход через Telegram приходят первыми** (проверено в ShopperTodo и ServicePlanner), поэтому Telegram не откладывается на потом. Приглашение в окружение остаётся одноразовой ссылкой. Архитектуру фиксирует IF-44 (Opus). Разблокирует IF-37 и IF-10.
5. **Ширина панели поверх контента: одно значение везде**, вместо 380 или 420. Значение выбирает Opus в IF-23 и записывает причину в `development/ui-mockup.md`.
6. **Переезд на Vite 8 после доработок UI по макету** (этап 9, IF-43).
7. **Порядок исполнения и модели** описаны в разделе «Правила исполнения».

## Как обновлять карту

1. Закрыл задачу или изменил зависимость: поправь строку этапа здесь и карточку в Ticket Board в одном заходе.
2. Новая доска или компонент: сначала `development/ui-mockup.md` и реестр в скиле `ifinances-ui`, потом таблица «Пробелы» здесь.
3. Срез кода в начале файла обновляй при закрытии этапа, пересчитывая теми же grep-запросами (литералы, брейкпоинты, z-index).
